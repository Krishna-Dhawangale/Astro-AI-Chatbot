1. EXECUTIVE SUMMARY & GUIDING PRINCIPLES
--------------------------------------------------------------------------------
This plan establishes a safe, multi-stage implementation to resolve intent routing 
issues (such as "Tell me my current Dasha and how my career will be" predicting raw 
intent="health_period" @ 13% confidence) across Phases 4–10.

STRICT CONSTRAINTS & GUARANTEES:
1. Raw ML Intent Preservation: raw_intent, raw_confidence, resolved_intent, and 
   resolution_reason are ALL preserved and logged. raw_intent is NEVER overwritten.
2. Smart Intent Overlay: Overlays do not trigger purely because confidence < 0.50. 
   Selection considers probability distribution, multi-intent signals, and question structure.
3. Multi-Domain First: Multi-domain detection occurs BEFORE intent correction.
4. Deterministic Multi-Domain Merger: Dasha API answer + Stage 8 Career local answer 
   are combined deterministically (gemini_calls == 0). Gemini handles ONLY unresolved portions.
5. Category M is Evaluation-Only Initially: Multi-model evaluation does NOT 
   automatically replace production models or activate ensembles without explicit human approval.
6. Zero Unapproved Changes: Code changes will NOT be executed until this plan 
   is reviewed and explicitly approved.

3. PHASES 4 TO 10 REVISED ROADMAP
--------------------------------------------------------------------------------

PHASE 4: Intent ML + Intent Resolution Overlay
- File: backend/router/intent.py
- Flow: Question -> get_intent_model() -> (raw_intent, confidence, probabilities) -> Intent Overlay -> (resolved_intent, resolution_reason).
- Log trace:
  [INTENT LOG] RAW INTENT: health_period (Conf: 0.13) | RESOLVED INTENT: multi_domain | RESOLUTION REASON: dasha_signal + career_signal.

PHASE 5: Multi-Domain Question Decomposition
- File: backend/router/pipeline.py & backend/main.py
- Recognize multi-domain signals before intent correction.
- Decompose query into sub-questions (e.g. Dasha sub-question + Career sub-question).

PHASE 6: Deterministic Dasha + Stage 8 Reasoning Answer Generation
- File: backend/main.py
- Execute Dasha API lookup for Dasha sub-question.
- Execute Stage 8 Reasoning Engine + interpretation.py for Career sub-question.
- Merge both answers deterministically without LLM intervention.

PHASE 7: Gemini Fallback for Unresolved Portions Only
- File: backend/main.py
- If all sub-questions are answered locally: gemini_calls = 0.
- If a sub-question is unresolved: pass ONLY the unresolved part to Gemini with structured evidence context.

PHASE 8: Multi-Model Domain Comparison & Evaluation Framework
- File: compare_domain_models.py (and backend/router/domain.py)
- Evaluate OLD, CONTEXT_V1, and V3 domain model pairs on validation datasets.
- Compare Accuracy, per-class Precision/Recall/F1, Confusion Matrix, Confidence Calibration.
- Generate Evaluation Report for human review before any production model selection.

PHASE 9: Full Regression + API + Schema + Gemini-Call Verification
- File: run_acceptance_tests.py
- Test explicit regression sets:
  * Health Set (8 questions)
  * Relationship Set (5 questions)
  * Multi-Domain Set ("Tell me my current Dasha and how my career will be.")
- Assert for every question: domain, intent, complexity, route, requires_chart, gemini_calls, final_source.

PHASE 10: Permanent Test Suite (Categories A through M) & Production Integration
- File: run_acceptance_tests.py
- Include 13 permanent test categories:
  A. FAQ
  B. Domain classification
  C. Complexity classification
  D. Intent classification
  E. Multi-domain resolution
  F. API retrieval
  G. Normalization boundary
  H. Reasoning engine
  I. Local answer formatting
  J. Gemini zero-call verification
  K. Response schema contract
  L. Frontend compatibility
  M. Model Selection / Ensemble Validation (Evaluation-only initially)


4. PROPOSED FILE MODIFICATIONS (UNDER CONSTRAINT 11)
--------------------------------------------------------------------------------

[FILE 1: backend/router/intent.py]
- Existing Behavior: predict_intent() returns raw prediction without confidence or resolution overlay.
- Proposed Change:
  1. Add predict_intent_with_confidence(question) returning (raw_intent, raw_confidence, probabilities).
  2. Add resolve_intent_overlay(question, raw_intent, raw_confidence, probabilities) implementing multi-domain signal detection first.
  3. Preserve raw_intent, raw_confidence, resolved_intent, and resolution_reason without overwriting raw_intent.
- Reason: Fixes "health_period" misclassification on Dasha+Career queries.
- Possible Regression: Existing single-intent classifications could be affected if the overlay incorrectly detects multiple domains. Raw ML predictions must remain unchanged, and all overlay decisions must be logged and covered by regression tests.
- How It Will Be Tested: Verify "Tell me my current Dasha and how my career will be." outputs raw_intent="health_period", resolved_intent="multi_domain", resolution_reason="dasha_signal + career_signal".

[FILE 2: backend/main.py]
- Existing Behavior: Handles single-domain queries and simple Dasha queries. Multi-domain complex queries fall through to Gemini stream.
- Proposed Change:
  Add deterministic multi-domain merger for resolved_intent == "multi_domain".
- Reason: Achieves gemini_calls == 0 for multi-domain questions where all sub-questions are locally answerable.
- Possible Regression: The deterministic merger could produce incomplete answers if one sub-question lacks sufficient evidence. Gemini must remain available for only the unresolved portion.
- How It Will Be Tested: Assert gemini_calls == 0 and response contains both Dasha and Career deterministic answers.

[FILE 3: run_acceptance_tests.py]
- Existing Behavior: Tests domain classification and basic pipeline.
- Proposed Change: Expand into 13-category test suite (A through M) with Category M being evaluation-only initially. Assert domain, intent, complexity, route, requires_chart, gemini_calls, final_source.
- Reason: Provides permanent regression protection.
- Possible Regression: None (test suite runner).
- How It Will Be Tested: Execute run_acceptance_tests.py and verify 100% PASS across all 13 categories.
